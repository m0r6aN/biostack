## Deterministic verification

Run from the coordinator-named isolated P1 worktree after committing all eight deliverables and force-adding `AGENTS.md`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File docs/specs/scripts/verify-p1.ps1 -BaseCommit <40-character-Gate-2-base-SHA> -EvidenceDirectory artifacts/p1-verification
```

The angle-bracket value exists only in this invocation example. The Gate 2 record contains the literal 40-character SHA. The verifier accepts only a 40-character hexadecimal commit, resolves it with `git rev-parse --verify`, and exits nonzero on any failure.

`verify-p1.ps1` must implement exactly these checks without network access or non-PowerShell dependencies:

1. Set `$ErrorActionPreference = 'Stop'`; resolve and enter `git rev-parse --show-toplevel`; verify `HEAD` descends from `BaseCommit`.
2. Run `git diff --check "$BaseCommit...HEAD"`; require exit `0`.
3. Read `git diff --name-only "$BaseCommit...HEAD" --`; require the changed set to equal—not merely be a subset of—the eight exact allowed surfaces in this spec, sorted ordinally.
4. Require `Test-Path -LiteralPath` for all eight deliverables and all seven core-context targets.
5. Require `git ls-files --error-unmatch -- AGENTS.md` to exit `0`; normalize CRLF to LF; compute UTF-8 SHA-256; require `C5163E1340C11613DD7DCAF6A4AC150589CA996C54EFD810BE96958C0DF4D944`; require each Appendix B marker exactly once.
6. Require the first nonblank `INDEX.md` line to equal `| Parcel | Status | Spec | Goal Charter | Delivery classes | Guidance classes | Branch/worktree | Owner | Review requirement | Closure |`; require exactly one row beginning `| P1 |`; split after removing leading/trailing pipes and require exactly ten cells.
7. For each Markdown file in the eight deliverables, parse inline links matching `\[[^\]]+\]\(([^)]+)\)`. Skip only `http://`, `https://`, `mailto:`, and fragment-only targets. Remove any fragment from local targets, URI-decode the path, resolve it relative to the source file, and require `Test-Path -LiteralPath`. Empty local targets fail.
8. Search all eight deliverables for unresolved markers matching `(?im)(^\s*(TBD|TODO|FIXME)\s*[:|\-])|(\{\{[^}]+\}\})|(<(BASE|BRANCH|WORKTREE|OWNER|REVIEWER)[^>]*>)`; require zero matches.
9. Require `git diff --quiet "$BaseCommit...HEAD" -- frontend backend contracts .github` to exit `0`.
10. Require `git diff --quiet "$BaseCommit...HEAD" -- docs/INITIATIVES/biostack-production-readiness docs/INITIATIVES/biostack-governed-delivery/CHARTER.md docs/INITIATIVES/biostack-governed-delivery/PLAN-REVIEW.md` to exit `0`.
11. Require `docs/INITIATIVES/biostack-production-readiness/README.md` to contain `**Status:** active, release blocked. **Recommendation:** **NO-GO / HOLD**.` exactly once.
12. Create the evidence directory, then write UTF-8/LF `changed-files.txt`, `link-results.json`, `index-row.txt`, `agents-sha256.txt`, and `verification-summary.json`. The summary contains each numbered check with `pass: true`, the base and head commits, and no warning state. Print `P1 verification PASS` and exit `0` only after all files are written.

Any exception, nonzero child-command exit where zero is required, missing evidence file, or warning state is red. There is no exclusion list and no warning-only acceptance.

# RTK (Rust Token Killer) - Token-Optimized Commands

When running shell commands, **always prefix with `rtk`**. This reduces context
usage by 60-90% with zero behavior change. If rtk has no filter for a command,
it passes through unchanged — so it is always safe to use.

## Key Commands
```bash
# Git (59-80% savings)
rtk git status          rtk git diff            rtk git log

# Files & Search (60-75% savings)
rtk ls <path>           rtk read <file>         rtk grep <pattern>
rtk find <pattern>      rtk diff <file>

# Test (90-99% savings) — shows failures only
rtk pytest tests/       rtk cargo test          rtk test <cmd>

# Build & Lint (80-90% savings) — shows errors only
rtk tsc                 rtk lint                rtk cargo build
rtk prettier --check    rtk mypy                rtk ruff check

# Analysis (70-90% savings)
rtk err <cmd>           rtk log <file>          rtk json <file>
rtk summary <cmd>       rtk deps                rtk env

# GitHub (26-87% savings)
rtk gh pr view <n>      rtk gh run list         rtk gh issue list

# Infrastructure (85% savings)
rtk docker ps           rtk kubectl get         rtk docker logs <c>

# Package managers (70-90% savings)
rtk pip list            rtk pnpm install        rtk npm run <script>
```

## Rules
- In command chains, prefix each segment: `rtk git add . && rtk git commit -m "msg"`
- For debugging, use raw command without rtk prefix
- `rtk proxy <cmd>` runs command without filtering but tracks usage
